# Распознавание голосовых команд

## Техническое задание

Необходимо реализовать программное решение для автоматического
распознавания голосовой команды из аудиофайла с использованием
готовой модели машинного обучения.

На вход программы подаётся аудиофайл, содержащий одно короткое
английское слово или голосовую команду.

Программа должна определить, какая команда была произнесена,
и вывести наиболее вероятный класс, а также оценку уверенности модели.

## Используемая модель

Для решения задачи распознавания голосовых команд используется модель
`MIT/ast-finetuned-speech-commands-v2`.

Модель основана на архитектуре Audio Spectrogram Transformer (AST) и
предназначена для классификации аудиозаписей по классам датасета
Speech Commands v2.

AST преобразует аудиосигнал в спектрограмму, после чего обрабатывает её
с помощью архитектуры Transformer, аналогичной Vision Transformer (ViT),
применяемой для изображений.

Модель была дообучена на датасете Speech Commands v2 и позволяет
классифицировать короткие аудиозаписи с отдельными английскими словами
и голосовыми командами.

Для запуска модели используется библиотека Hugging Face Transformers
через `audio-classification` pipeline.

Размер модели составляет около 85.4 млн параметров.

## Преимущества библиотеки Hugging Face Transformers

Для работы с моделью используется библиотека Hugging Face Transformers.

Основные преимущества:

- готовый `pipeline("audio-classification")` для классификации аудио
- автоматическая загрузка модели и её конфигурации
- автоматическая подготовка входных аудиоданных
- получение результата в удобном формате `label + score`
- возможность использовать готовую модель без собственного обучения
- локальный inference без обращения к внешнему API

## Принцип работы модели 

Модель `MIT/ast-finetuned-speech-commands-v2` основана на архитектуре
Audio Spectrogram Transformer (AST).

AST предназначен для классификации аудио и работает по принципу,
похожему на Vision Transformer (ViT), но вместо обычного изображения
модель анализирует спектрограмму звукового сигнала. В оригинальной статье
AST описывается как модель для аудиоклассификации без использования
сверточных нейронных сетей: основная обработка выполняется с помощью
механизма self-attention. 

### 1. Получение аудиосигнала

На вход модели подаётся аудиозапись.

Аудиосигнал представляет собой последовательность значений амплитуды
во времени. В используемой реализации вход должен быть одноканальным
(mono), а feature extractor модели преобразует исходный сигнал в признаки,
необходимые AST. 

### 2. Преобразование аудио в log-Mel спектрограмму

Непосредственно необработанный аудиосигнал не передаётся в Transformer.

Сначала из него извлекаются Mel filter-bank признаки. Они представляют
звук в виде двумерной структуры, близкой к изображению спектрограммы:

- одна ось соответствует времени
- вторая - частотам
- значения показывают интенсивность звука в соответствующий момент
  времени и частотном диапазоне

В реализации Hugging Face для AST используется 128 Mel-частотных полос.
Полученные признаки также нормализуются и приводятся к фиксированной
длине перед передачей в модель.

Таким образом, исходное аудио превращается примерно в такую структуру:

`аудиосигнал -> log-Mel спектрограмма`

### 3. Разбиение спектрограммы на patches

После получения спектрограммы AST работает с ней аналогично Vision
Transformer.

Спектрограмма разбивается на небольшие прямоугольные участки — `patches`.
В стандартной конфигурации AST размер patch составляет 16×16 элементов.
Участки выделяются вдоль временной и частотной осей. 

Каждый patch преобразуется в числовой вектор — embedding.

В результате вместо одной большой спектрограммы Transformer получает
последовательность небольших представлений отдельных участков звука.

То есть:

`спектрограмма - patches - embeddings`

### 4. Обработка patches с помощью Transformer

Полученная последовательность embeddings передаётся в Transformer.

В конфигурации используемой AST-модели используются Transformer-слои
с механизмом self-attention. Self-attention позволяет модели учитывать
взаимосвязи между разными участками спектрограммы, в том числе находящимися
далеко друг от друга по времени или частоте. 

Например, при распознавании слова модель может учитывать не только
отдельный короткий звук, но и взаимосвязь между началом, серединой
и окончанием произнесённой команды.

Это одно из ключевых отличий AST от классических подходов на основе CNN:
AST построен как attention-based модель и способен сразу учитывать
глобальный контекст всей спектрограммы. В оригинальной работе AST
описывается как первая полностью attention-based, convolution-free
модель для аудиоклассификации.

### 5. Формирование общего представления аудио

После прохождения через Transformer модель получает представление,
содержащее информацию о всей аудиозаписи.

Внутри Transformer постепенно формируется набор признаков,
характеризующих структуру звука: частотные компоненты, их расположение
во времени и взаимосвязи между различными частями произнесённого слова.

Это представление передаётся в классификационную часть модели.

### 6. Классификация голосовой команды

Финальный слой выполняет классификацию аудиозаписи по фиксированному
набору классов Speech Commands v2.

Например, среди классов модели присутствуют команды:

`yes`, `no`, `up`, `down`, `left`, `right`, `on`, `off`, `stop`, `go`
и другие.

Конфигурация конкретной модели содержит соответствие между числовыми
идентификаторами классов и названиями команд. 

На выходе модель формирует оценки для всех доступных классов.
Hugging Face `audio-classification` pipeline преобразует эти значения
в удобный результат вида:

`label + score`

Например:

`down — 99.98%`

Категория с наибольшим `score` выбирается как наиболее вероятная
голосовая команда.

### Общая схема работы

`аудиофайл`
→ `аудиосигнал`
→ `log-Mel спектрограмма`
→ `разбиение на patches`
→ `embeddings`
→ `Transformer + self-attention`
→ `классификатор`
→ `голосовая команда + score`

Основная идея AST заключается в том, что аудио сначала представляется
как двумерная спектрограмма, после чего к ней применяется подход,
аналогичный Vision Transformer. Благодаря self-attention модель может
анализировать взаимосвязи между разными временными и частотными участками
аудиосигнала и на основании полученного представления определять класс
голосовой команды.

## Причины выборы модели

Основная причина выбора — прямое соответствие поставленной задаче.
Модель специально дообучена для классификации аудио по классам датасета
Speech Commands v2, то есть для распознавания коротких голосовых команд
и отдельных слов. Это совпадает с задачей нашей программы.

Дополнительным аргументом в пользу выбора является высокое качество модели.
В карточке модели на Hugging Face указана Accuracy 98.12%
на Speech Commands v2.

Также модель имеет около 85.4 млн параметров, поэтому она значительно
компактнее крупных генеративных моделей и может использоваться локально
для inference.

Таким образом, модель была выбрана по следующим причинам:

- она специально обучена для Speech Commands v2
- её задача совпадает с задачей распознавания голосовых команд
- опубликованная Accuracy составляет 98.12%
- модель поддерживает локальный inference
- доступна готовая интеграция с Hugging Face Transformers
- не требуется дополнительное обучение или дообучение

## Структура датасета
Для дообучения модели используется датасет `Speech Commands v2`.

Speech Commands v2 предназначен для задачи Keyword Spotting —
распознавания заранее известных коротких голосовых команд.

Датасет содержит 105 829 аудиофайлов. Каждый файл представляет собой
короткую `.wav`-запись с одним произнесённым английским словом или
фоновым шумом. Частота дискретизации аудио составляет 16 kHz.

Версия v0.02 разделена на три части:

- `train` — 84 848 примеров
- `validation` — 9 982 примера
- `test` - 4 890 примеров

Каждая запись датасета содержит следующие поля:

- `file` — путь к исходному аудиофайлу
- `audio` — аудиосигнал, включающий массив значений waveform и
  `sampling_rate`
- `label` — числовой идентификатор класса
- `is_unknown` — показывает, относится ли слово к дополнительным,
  а не основным командам
- `speaker_id` — идентификатор человека, произнёсшего слово
- `utterance_id` — номер конкретного произнесения слова этим человеком

Пример структуры записи:

{
    "file": "no/7846fd85_nohash_0.wav",
    "audio": {
        "array": [...],
        "sampling_rate": 16000
    },
    "label": 1,
    "is_unknown": false,
    "speaker_id": "7846fd85",
    "utterance_id": 0
}

В данном примере значение `label = 1` соответствует слову `no`.

## Классы датасета

В Speech Commands v2 присутствуют 35 произносимых слов и дополнительный
класс `_silence_`.

К основным голосовым командам относятся:

`yes`, `no`, `up`, `down`, `left`, `right`, `on`, `off`, `stop`, `go`.

Также в датасете присутствуют дополнительные слова:

`zero`, `one`, `two`, `three`, `four`, `five`, `six`, `seven`,
`eight`, `nine`, `bed`, `bird`, `cat`, `dog`, `happy`, `house`,
`marvin`, `sheila`, `tree`, `wow`, `backward`, `forward`, `follow`,
`learn`, `visual`.

Класс `_silence_` содержит фоновый шум.

Поле `is_unknown` позволяет отделять основные команды от дополнительных
слов. Дополнительные слова нужны для того, чтобы модель могла научиться
отличать известные команды от посторонних слов.

В нашей реализации используются аудиофайлы, содержащие отдельные
голосовые команды из Speech Commands v2. Модель получает аудиозапись
и определяет наиболее вероятный класс команды.

## Метрики качества модели

Для оценки качества модели используется метрика `Accuracy`.

Accuracy показывает долю правильно классифицированных аудиозаписей
от общего количества проверенных примеров.

Для архитектуры Audio Spectrogram Transformer на датасете
Speech Commands V2 опубликована Accuracy около 98.1%. Это означает,
что модель правильно определяет голосовую команду примерно в 98 случаях
из 100 на соответствующем тестовом наборе. 

### Результаты собственной проверки

Для проверки реализации был использован набор из 24 аудиофайлов
с командами:

`down`, `go`, `left`, `no`, `right`, `stop`, `up`, `yes`.

Для каждого файла название папки использовалось как правильный класс,
после чего результат модели автоматически сравнивался с ожидаемым.

Результаты:

- проверено аудиофайлов — 24
- правильно классифицировано — 24 из 24
- Accuracy — 100%
- среднее время inference одного файла — 0.093 секунды

Полученное значение Accuracy 100% относится только к данному небольшому
тестовому набору и не означает, что модель будет иметь Accuracy 100%
на любых аудиозаписях.

## Особенности реализации алгоритма и его эффективность

Реализация построена на готовом `audio-classification` pipeline
библиотеки Hugging Face Transformers.

Алгоритм работы программы:

1. Пользователь вводит путь к аудиофайлу.
2. Программа проверяет существование файла.
3. Аудиофайл передаётся в модель
   `MIT/ast-finetuned-speech-commands-v2`.
4. Pipeline автоматически подготавливает аудиоданные и выполняет inference.
5. Модель вычисляет оценки для всех доступных классов Speech Commands v2.
6. Результаты сортируются по значению `score`.
7. Пользователю выводится наиболее вероятная команда, её score,
   а также несколько наиболее вероятных вариантов.

Основная часть inference реализована одной командой:

`classifier(str(path), top_k=5)`

Параметр `top_k=5` позволяет получить пять классов с наибольшими
значениями score.

Модель загружается один раз при запуске программы, после чего может
использоваться для обработки аудиофайлов без повторной загрузки весов.

Для отдельной проверки качества был реализован файл `evaluate.py`.
Он автоматически находит `.wav`-файлы в тестовых папках,
использует название папки как ожидаемый класс и сравнивает его
с результатом модели.

Во время тестирования также измерялось время inference с помощью
`time.perf_counter()`.

На тестовом наборе из 24 аудиофайлов были получены следующие результаты:

- Accuracy — 100%
- правильно классифицировано — 24 из 24 файлов
- среднее время inference — 0.093 секунды на один аудиофайл

Таким образом, решение не требует собственного обучения модели,
имеет небольшое время обработки коротких аудиозаписей и может
выполнять классификацию локально на компьютере пользователя.

Следует учитывать, что модель работает с фиксированным набором классов
Speech Commands v2 и не предназначена для распознавания произвольной речи
или преобразования речи в текст.
