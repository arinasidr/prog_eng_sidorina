# Определение темы текста

## Техническое задание
Необходимо реализовать программное решение для автоматического определения тематики текстового сообщения с использованием готовой модели машинного обучения.

На вход программы подаётся текст на русском или другом поддерживаемом моделью языке, а также набор возможных тематических категорий, например: «технологии», «спорт», «бизнес», «образование».

Программа должна определить, к какой из заданных категорий наиболее вероятно относится входной текст, и вывести название категории и соответствующую оценку уверенности модели.

## Используемая модель
Для решения задачи используется модель:

`MoritzLaurer/mDeBERTa-v3-base-xnli-multilingual-nli-2mil7` 

Модель предназначена для вывода естественного языка (NLI) на 100 языках и, следовательно, также подходит для классификации с zero-shot classification

Для работы с моделью используется библиотека Hugging Face Transformers

## Преимущества библиотеки

Hugging Face Transformers предоставляет готовые инструменты для работы
с предобученными моделями машинного обучения.

В данной работе используется `pipeline` для Zero-Shot Classification,
который позволяет загрузить готовую модель и выполнять классификацию
без её дополнительного обучения.

Основные преимущества библиотеки:

- простой запуск готовых моделей
- автоматическая загрузка модели и токенизатора
- поддержка большого количества предобученных моделей
- возможность выполнять inference локально
- наличие готового pipeline для Zero-Shot Classification

## Принцип работы модели 

Модель основана на архитектуре mDeBERTa-v3 и предназначена для задачи
Natural Language Inference (NLI).

В задаче NLI модель получает два текста:

- `premise` — исходное утверждение
- `hypothesis` — гипотеза, которую необходимо проверить.

После этого модель определяет отношение между ними и относит пару к одному
из трёх классов:

- `entailment` — исходный текст подтверждает гипотезу
- `neutral` — по исходному тексту нельзя однозначно подтвердить или
  опровергнуть гипотезу
- `contradiction` — исходный текст противоречит гипотезе.

В данной работе механизм NLI используется для Zero-Shot Classification.

Пользователь передаёт исходный текст и список возможных тематических
категорий. Каждая категория преобразуется в гипотезу, после чего модель
оценивает, насколько исходный текст ей соответствует.

Например, для текста:

`Команда выиграла финальный матч чемпионата`

и категории `спорт` формируется гипотеза о том, что данный текст относится
к спорту. Модель оценивает степень соответствия текста этой гипотезе.

Аналогичная проверка выполняется для каждой переданной категории.
Категория с наибольшей оценкой соответствия считается наиболее вероятной
темой текста.

Этот подход как раз и называется Zero-Shot Classification, поскольку модель не
обучается отдельно на конкретных категориях, используемых в программе.
Список категорий можно изменять во время работы программы без повторного
обучения модели.

В основе модели находится multilingual-версия DeBERTaV3. DeBERTa использует
механизм Disentangled Attention, в котором отдельно учитываются содержание
токена и его положение относительно других токенов. Версия DeBERTaV3 также
использует подход Replaced Token Detection при предварительном обучении.

## Причины выборы модели

Основная причина выбора — соответствие модели поставленной задаче.
Модель специально предназначена для Natural Language Inference (NLI)
и может использоваться для multilingual Zero-Shot Classification.
В карточке модели прямо указано, что она подходит для zero-shot
классификации на нескольких языках, а в документации Hugging Face
показан готовый способ её использования через
`pipeline("zero-shot-classification")`.

Важным фактором является поддержка русского языка. Базовая
`mDeBERTa-v3-base` была предварительно обучена на мультиязычном корпусе
CC100, содержащем 100 языков. После этого модель была дополнительно
дообучена на NLI-датасетах XNLI и
`multilingual-NLI-26lang-2mil7`. Русский язык входит в число языков,
использовавшихся при NLI-дообучении модели.

Ещё одной причиной выбора является возможность классифицировать текст
по произвольному набору категорий без дополнительного обучения модели.
В Zero-Shot Classification пользователь сам передаёт список
`candidate_labels`, а Hugging Face преобразует каждую категорию в
NLI-гипотезу и оценивает её соответствие исходному тексту.

Благодаря этому список тематик не является фиксированным. Например,
вместо категорий `спорт`, `бизнес`, `образование`, `технологии`
пользователь может передать другой набор категорий без повторного
обучения или дообучения модели.

Дополнительным аргументом в пользу выбора модели являются опубликованные
результаты её оценки. На тестовой части XNLI для русского языка автор
модели указывает Accuracy 0.803, то есть около 80.3%. Это позволяет
оценивать модель не только по субъективным примерам, но и опираться на
опубликованные результаты на стандартном NLI-бенчмарке.

Модель также удобна для локальной реализации: она доступна через
Hugging Face Transformers и может быть загружена как готовая
предобученная модель. Размер модели составляет около 0.3 млрд параметров,
что значительно меньше крупных генеративных LLM на несколько миллиардов
или десятков миллиардов параметров и позволяет использовать её локально
для inference без обращения к внешнему API.

Таким образом, модель была выбрана из-за сочетания следующих факторов:

- прямое соответствие задаче Zero-Shot Classification
- поддержка русского языка
- возможность использовать произвольные категории без обучения модели
- наличие опубликованных метрик качества
- возможность локального запуска
- готовая интеграция с Hugging Face Transformers

## Структура датасета

Для NLI-дообучения модели использовались два датасета:

1. `MoritzLaurer/multilingual-NLI-26lang-2mil7`
2. validation-часть `XNLI

### multilingual-NLI-26lang-2mil7

Датасет содержит 2 730 000 NLI-пар `premise-hypothesis`
на 26 языках. Дополнительно автор использовал выборку английских
примеров, сформированную тем же способом.

Датасет разделён на 130 split'ов — по одному для каждой комбинации
языка и исходного NLI-датасета.

Название split имеет формат:

`{код_языка}_{название_датасета}`

Например: `ru_mnli`

Каждая запись содержит следующие поля:

- `premise_original` — исходный premise на английском языке
- `hypothesis_original` — исходная hypothesis на английском языке
- `premise` — premise, переведённый на целевой язык
- `hypothesis` — hypothesis, переведённая на целевой язык
- `label` — класс отношения между premise и hypothesis.

Поле `label` принимает одно из трёх значений:

- `0` — entailment
- `1` — neutral
- `2` — contradiction.

Таким образом, одна запись датасета представляет собой пару текстов
и правильный класс логического отношения между ними.

### XNLI

Дополнительно при дообучении модели использовалась validation-часть
датасета XNLI.

XNLI также предназначен для задачи Natural Language Inference и имеет
аналогичную структуру.

Каждая запись содержит три основных поля:

- `premise` — исходный текст
- `hypothesis` — гипотеза
- `label` — класс отношения между текстами.

Поле `label` также имеет три значения:

- `0` — entailment
- `1` — neutral
- `2` — contradiction.

Датасет содержит отдельные конфигурации для разных языков, в том числе
для русского языка (`ru`).

Validation-часть для каждого языка содержит 2 490 примеров.

## Метри оценки качества модели

Для оценки качества модели используются как опубликованные ML-метрики,
так и собственные измерения, полученные при тестировании реализованного решения.

### Опубликованные метрики модели

В карточке модели на Hugging Face приведены результаты на нескольких
NLI-бенчмарках.

Для русского поднабора XNLI указана:

- Accuracy — 0.803, то есть 80.3%. (доля правильных ответов модели)

Для сравнения, на английском поднаборе XNLI модель показывает
Accuracy 0.871, то есть 87.1%.

Также в карточке модели приведены результаты на других NLI-датасетах:

- MultiNLI matched — 85.7% (MultiNLI содержит NLI-примеры из разных жанров письменной и устной речи. В режиме `matched` модель проверяется на текстах из тех же жанров,
  которые представлены в обучающей части MultiNLI.)
- MultiNLI mismatched — 85.6% (В варианте `mismatched` модель тестируется на жанрах текстов,
  которые не представлены в обучающем наборе MultiNLI.)
- ANLI all — 53.7% (ANLI (Adversarial Natural Language Inference) — более сложный
  NLI-бенчмарк, примеры которого специально создавались таким образом,
  чтобы быть трудными для существующих моделей.
  При создании датасета использовался итеративный подход
  human-and-model-in-the-loop: люди формировали примеры с учётом ошибок,
  которые совершали модели. `ANLI all` объединяет тестовые данные трёх раундов ANLI.)
- ANLI round 3 — 49.7% (Это результат только на третьем раунде ANLI, то есть на самом сложных случаях)
- FEVER-NLI — 76.1% (FEVER изначально предназначен для проверки фактических утверждений:
  необходимо определить, подтверждается утверждение имеющимися
  текстовыми доказательствами, опровергается ими или для вывода
  недостаточно информации)
- LingNLI — 78.8% (LingNLI содержит NLI-примеры, при сборе которых использовалось
  участие специалистов по лингвистике.)
- WANLI — 73.2% ( WANLI (Worker and AI Collaboration for NLI) создавался совместно
  человеком и языковой моделью.)

Эти значения характеризуют способность модели решать исходную задачу
Natural Language Inference и не являются точностью именно нашей
тематической классификации.

Для каждого текста заранее была известна правильная категория.

## Особенности реализации алгоритма и его эффективность

Алгоритм работы программы состоит из следующих этапов:

1. Пользователь вводит текст, для которого необходимо определить тему
2. Пользователь может указать собственный список тематических категорий
3. Если список категорий не указан, используются стандартные категории:
   `технологии`, `спорт`, `бизнес`, `образование`
4. Исходный текст и список категорий передаются в
   `zero-shot-classification` pipeline библиотеки Hugging Face Transformers
5. Для каждой категории модель оценивает степень её соответствия
   исходному тексту.
6. Категории сортируются по значению `score`
7. Категория с максимальным значением `score` выбирается как наиболее
   вероятная тема текста
8. Пользователю выводится выбранная тема, её оценка уверенности,
   а также оценки остальных категорий

### Особенности реализации

Главной особенностью решения является отсутствие необходимости
обучать или дообучать модель для конкретного набора тематических
категорий.

Категории передаются модели непосредственно во время выполнения программы,
поэтому пользователь может изменить их без изменения весов модели.

Для взаимодействия с моделью используется высокоуровневый
`pipeline` библиотеки Hugging Face Transformers, который автоматически
выполняет подготовку входных данных, запуск модели и обработку результата.

Модель загружается один раз при запуске программы и далее может
использоваться для классификации введённых текстов.

### Эффективность

Эффективность реализации оценивалась по времени выполнения inference.

На локальном тестировании среднее время классификации одного текста
составило 0.192 секунды.

При тестировании на 12 примерах модель правильно классифицировала
12 из 12 текстов, поэтому Accuracy на данном тестовом наборе составила 100%.

Одним из преимуществ Zero-Shot Classification является отсутствие затрат
на дополнительное обучение при добавлении новых тематических категорий.

При этом вычислительные затраты зависят от количества переданных категорий:
чем больше возможных тем необходимо проверить, тем больше сравнений
должна выполнить модель и тем больше времени может занимать inference.

Таким образом, выбранный подход удобен для задач, в которых список
категорий может изменяться, а дополнительное обучение модели нежелательно.
